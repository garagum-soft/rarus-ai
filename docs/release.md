## Шаг 4. Выпуск

1. Поднять `__version__` в `app/rarus_app/__init__.py` (сейчас `0.1.4`; версия установщика берётся оттуда же, `build.ps1` без `-Version` читает её сам), закоммитить.
2. `git tag vX.Y.Z && git push origin vX.Y.Z` — версия тега обязана совпасть с `__version__`, иначе сборка остановится. Версии 0.1.1 и 0.1.2 уже выложены вручную (см. ниже), поэтому первый выпуск через Actions — со следующей версией (0.1.3), а не с тега `v0.1.2`.
3. Actions соберёт установщик (около 30–40 минут), проверит SHA-256 после передачи и на сервере и
   подменит `RarusAI-Setup.exe` атомарно, раньше `version.txt`; предыдущий кладётся рядом как `.bak`.
4. Вручную без тега: Actions → Rarus Release → Run workflow → `publish`.

## Выкладка без GitHub (так выложены 0.1.0–0.1.4)

Положить уже собранный файл, не дожидаясь Actions (`build\RarusSetup-<версия>.exe`, SHA-256 в
`build\RarusSetup-<версия>.sha256`). Файл сначала грузится под временным именем и сверяется на сервере,
потом старый уходит в `.bak`, новый встаёт на место, и только после этого пишутся `sha256.txt` и `version.txt`
(программа смотрит на `version.txt`, поэтому он последний):

```bash
V=0.1.1
SHA=$(sha256sum build/RarusSetup-$V.exe | cut -d' ' -f1)
K="-i $HOME/.ssh/claude_alembox -o BatchMode=yes -o IdentitiesOnly=yes"
scp -q $K -P 39 build/RarusSetup-$V.exe root@95.85.125.50:/opt/wan-site/data/desktop/rarus/RarusAI-Setup.exe.uploading
ssh $K -p 39 root@95.85.125.50 "cd /opt/wan-site/data/desktop/rarus \
  && [ \"\$(sha256sum RarusAI-Setup.exe.uploading | cut -d' ' -f1)\" = $SHA ] \
  && chown llm:llm RarusAI-Setup.exe.uploading && chmod 644 RarusAI-Setup.exe.uploading \
  && cp -p RarusAI-Setup.exe RarusAI-Setup.exe.bak && mv -f RarusAI-Setup.exe.uploading RarusAI-Setup.exe \
  && echo $SHA > sha256.txt && echo $V > version.txt && chown llm:llm sha256.txt version.txt"
```

Канал до VDS бывает медленным (18–19.10 то около 1 МБ/с, то около 50 КБ/с): 0.1.1 грузился 76 минут, 0.1.2 — 72, поэтому
загрузку запускают в фоне. Пока идёт загрузка, с той же машины почти не открываются и сами сайты (страницы больше
30 КБ зависают), а из внешней сети те же файлы отдаются нормально: проверка страниц — после загрузки или извне.

## Компоненты: что программа докачивает после установки (с 0.1.4)

Слово владельца (19.10): «как в Alem AI: при первом запуске показать, что будет скачано, со свичами; некоторые
нельзя выключить, некоторые включены, но выключаются; то, что входит в саму программу, — скрыто; всё — с нашего
сервера». В установщике остаётся сама программа (200 МБ в 0.1.4; 238 МБ в 0.1.3 — разница от версий из lock-файла); остальное — компоненты.

|---|---|---|---|
| Долговременная память | обязательный (видно, нельзя выключить) | 27 / 63 МБ | плагин `everos-memory` + EverOS 1.4.1 и то, чего ему не хватает в программе |
| Чтение документов | обязательный | 90 / 104 МБ | модели deepdoc (`det`, `rec`, `layout`, `tsr`, `ocr.res`) для PDF, сканов и таблиц |

Скрытых сейчас нет: панели, агенты, база знаний и всё остальное «самой программы» лежит в установщике и нигде не
перечисляется — это и есть то, что Alem AI прячет. Группа `hidden` в механизме есть (ставится в фоне, не
показывается). Словари для китайского токенизатора (`datrie`) в компоненты не вошли: на Windows `datrie` не
собирается без компилятора C++, а база знаний ищет через n-граммы LanceDB и этот токенизатор не использует.

**Как устроено.**
- Список — `packaging/components/catalog.json` (id, группа, названия ru/en, пакеты, что докачать, переменные
  окружения, проверка). Сборщик — `packaging/components/build.py` (шаг 5 `build.ps1`, после PyInstaller): ставит
  пакеты в отдельную папку по версиям из `engine/uv.lock`, выбрасывает всё, что уже есть внутри программы,
  докачивает данные (модели deepdoc с Hugging Face, Chromium с CDN Playwright), упаковывает в zip с фиксированными
  датами (одинаковое содержимое — тот же SHA-256 и то же имя, повторно не скачивается), распаковывает каждый в
  пробный дом и выполняет его `check` внутри собранной программы: память поднимает настоящий сервер EverOS
  (`RarusAI.exe --everos server start`) и ждёт ответа `/health`, документы открывают все четыре модели, браузер
  запускает Chromium и читает страницу, презентации, дизайн и мессенджеры импортируют каждый свой модуль. Каталог с хешами пишется внутрь
  программы (`_internal/rarus_app/components.json`) и в `build/components/out` рядом с архивами.
- PyInstaller кладёт в программу только те части библиотек, которые импортирует сам движок. Если компоненту
  нужна библиотека целиком, она указывается в `whole` (памяти нужен весь starlette — 0,3 МБ), и копия из
  компонента той же версии перекрывает частичную. Стандартная библиотека Python теперь в программе целиком
  (без тестов и tkinter): компонентам и агентам нужны модули, которых движок не трогает (`filecmp`).
- `-SkipComponents` берёт компоненты прошлой сборки. Зависимости, которых нет на Windows, сборщик ловит сам:
  cairosvg при виде PyInstaller ищет свои файлы в папке программы — в копии внутри компонента эта ветка
  выключена (`FIXUPS` в сборщике); библиотеки cairo на Windows нет, и движок презентаций обходится без неё (логотип
  в SVG остаётся текстом).
- Раздача: `https://rarus-ai.com/api/mirror/rarus/components/<id>-<sha12>.zip` — зеркало сайта, открыто без входа
  (список показывается до входа); на rarus-ai.com открыта только папка `rarus/` (`ALLOWED` в
  `wan-site/backend/rarus_main.py`), байты отдаёт nginx через `/protected/` с поддержкой Range. Файлы лежат в
  `/opt/wan-site/data/mirror/rarus/components/`, грузятся `scp` под временным именем со сверкой SHA-256 на сервере.
- Проверено с настоящего сервера: оболочка скачала все шесть компонентов (568 МБ) с rarus-ai.com в чистую папку
  за 192 с (3–4 МБ/с), все сверены и распакованы; `components_finish` снимает первый запуск.
- Программа (`app/rarus_app/components.py`): только https и только свои хосты (`ALLOWED_HOSTS` обновлятора),
  докачка с места обрыва (Range, 5 попыток), распаковка только после совпадения SHA-256 и без путей наружу, в
  `~/.rarus/components/<id>/<sha12>/`; `state.json` рядом — что стоит и что выбрано. Старая версия компонента
  удаляется при старте, если её держал работающий движок.
- Подключение: `RarusAI.exe` теперь умеет быть «python» — `script.py`, `-m модуль`, `-c код` и `--everos …`
  (`app/rarus_app/__main__.py`); каждый такой процесс (движок, агент, сервер EverOS) сначала ставит папки
  компонентов в начало `sys.path` и выставляет их переменные (`PLAYWRIGHT_BROWSERS_PATH`, `RAVEN_KNOWLEDGE_RES`,
  `RAVEN_BROWSER_CHANNEL`; `app/rarus_app/component_paths.py`). Сервер памяти запускается как
  `RarusAI.exe --everos server start` (переменная `EVEROS_CLI`, `raven_everos/server.py`).
- Первый запуск: стартовая страница окна показывает список до входа; движок стартует после ответа, поэтому сразу
  видит поставленное. Ошибка одного компонента не останавливает остальные: «Повторить» (только упавшие) или
  «Продолжить без них»; недостающее потом докачивается в фоне при каждом запуске. Кто обновился с 0.1.3, увидит
  список один раз при следующем запуске.
- Потом: «Настройки → Плагины → Компоненты» — те же переключатели, «Применить», ход скачивания и «Перезапустить
  сейчас» (движок перезапускается, окно возвращается на стартовую страницу и открывает программу снова).

**Попутно найдено и исправлено.**
- Агенты и нанятые сотрудники в собранной программе не запускались, по трём причинам сразу: (1) движок стартует
  их как `<python> run.py`, а python в собранной программе — сам `RarusAI.exe`, который вместо агента открывал
  окно; теперь он выполняет скрипт; (2) самих `run.py`, `install.py` и плагинов агентов в сборке не было —
  PyInstaller не кладёт .py-файлы как данные; теперь `agents/` и `templates/` едут целиком (`rarus.spec`);
  (3) на Windows `run.py` передаёт работу серверу ACP дочерним процессом, а оконный exe не получает stdin/stdout,
  если их не назвать явно; теперь они передаются (`exec_raven_acp`), а exec самого себя выполняется в том же
  процессе. Проверено на собранной программе: агент Raven-Code отвечает на `initialize` по ACP.
- Всё, что `RarusAI.exe` запускает как python, теперь читает и пишет UTF-8, как и CLI движка: в кодовой
  странице Windows EverOS падал на первой стрелке в справке, а русский текст от движка читался бы криво.
- Память EverOS не запустилась бы и с установленным компонентом: роль «модель памяти» берёт ключ провайдера, а
  провайдер Rarus числился OAuth и ключа не отдавал. Ключ программы Rarus долгоживущий, теперь он отдаётся
  (`resolve_provider_credentials`), и память по умолчанию идёт через аккаунт (кредиты списываются с него же).
  Эмбеддинги не настроены: без них EverOS ищет по словам.
- Сборка ставила самые новые версии библиотек, а не закреплённые в `engine/uv.lock` (внутри 0.1.3 был lancedb
  0.40 вместо 0.34, с которым несовместим EverOS). Теперь `build.ps1` экспортирует ограничения из lock-файла
  (`build/lock-constraints.txt`) и ставит по ним и программу, и компоненты.

## Домен rarus-ai.com: второй процесс на том же сервере, база общая

Слово владельца: «сервер Rarus AI запущен на том же сервере, где был alembox.com, на другом порту, но
регистрационная база у всех одна: alembox.com, sanlykatip.com и rarus-ai.com».

**Как устроено (готово локально, на сервер не выложено).** Тот же код сайта запускается вторым процессом
`uvicorn rarus_main:app` на `127.0.0.1:8120` (основной — `main:app` на 8000). Оба открывают один файл базы
(`WAN_DB_PATH`, SQLite в режиме WAL: так уже работают два воркера основного сайта) и читают один `.env` с
`WAN_JWT_SECRET`. Поэтому один аккаунт, один пароль, одни ключи программы (`sk-ab-…`) и один кошелёк на всех
трёх адресах; зарегистрированный на одном входит на другом, токен одного действителен на другом.
Второй процесс пропускает только нужное Rarus (вход, регистрация, «кто я», тарифы, профиль, Google, сброс
пароля, `/api/agent/`, `/api/desktop/rarus/`); всё остальное — 404, даже для админа. Рестарт Rarus не трогает
alembox.com. Уборщик задач остаётся у основного процесса.

|---|---|
| `backend/rarus_main.py` | второй процесс: тот же `main.app` за списком путей; сам подключает маршруты установщика, если `main.py` на сервере их ещё не знает |

**Кнопка обновления.** Настройки → «Аккаунт» → «Обновления»: «Проверить» спрашивает сайт (нужен вход);
если версия новее, появляется «Установить»: оболочка скачивает установщик (проценты на странице), проверяет
SHA-256, запускает `RarusAI-<версия>-setup.exe /S /UPDATE` из своей папки обновлений и закрывает окно
через 1,5 с; установщик ставит поверх, запускает программу и ничего не стирает в `~/.rarus`. Установщик
запускается только из папки обновлений, только с именем `RarusAI-<число>-setup.exe` и только после повторной
сверки хеша; отказ оставляет окно открытым с причиной на странице. Копия установщика работающей версии
хранится в `updates/previous` как путь назад. В обычном браузере (не окно Rarus) кнопка выключена, строка
подсказывает, где обновиться. Проверка живьём: поставить 0.1.0 или 0.1.1, войти, нажать «Проверить» — предложит 0.1.2.

**Автообновление (с 0.1.3, `engine/ui-web/src/app/autoUpdate.ts`).** Как в Alem AI: через минуту после запуска и
дальше каждые 10 минут страница просит оболочку проверить сайт (та же цепочка, что у кнопки: скачать, сверить
SHA-256). Когда установщик готов, один раз за запуск на версию появляется окно «Вышло обновление Rarus AI X» с
кнопкой «Обновить сейчас». Если на окно не ответили, через 10 минут программа ставит обновление сама, но только
когда ни одна беседа не выполняется (ход в этом окне и `running` в `session.list`) и окно не трогали минуту;
иначе ждёт дальше. «Отмена» — без обновления до следующего запуска. Окно, свёрнутое в трей, тоже обновляется.
Без входа сайт отвечает 401 — проверка тихо молчит. Работает только начиная с 0.1.3: с 0.1.2 и раньше
обновиться на 0.1.3 надо один раз кнопкой «Проверить». Сроки — `timing` в том же файле.

**Что стоит знать про общую базу:** кэши и счётчики в памяти (например, ограничения частоты) у каждого процесса
свои; запись в базу идёт через SQLite с ожиданием до 30 секунд, как у двух воркеров основного сайта.
Незакоммиченные правки соседней сессии в `wan-site/backend/agent_api.py` (колонка `effort` без миграции)
роняют 16 тестов `test_agent_api.py` в рабочем дереве — на чистой копии коммита и с моими правками все проходят.
